# 정합 plan(대조표) 템플릿

Figma 기획과 구현을 대조해 작업 항목을 쌓는 문서다. `snapshot-delta.mjs`는 §Sync 상태 표의 `Figma file version` 행을 게이트로 읽으므로 그 행의 형식은 고정이다. 나머지 절은 프로젝트에 맞게 줄이거나 늘린다. 꺾쇠 자리는 채운다.

```markdown
# <제품> Figma 정합 작업

## 전제

- 정본은 Figma이고 스냅샷(`<out 경로>`)은 추출 시점의 사본이다. 확정 디자인이 아니라 기획 **의미**를 읽는 용도다.
- 현재 동작은 언제나 source와 config가 권위다. 기획 설명은 가설이고 `file:line`으로 확인한 것만 판정에 쓴다.
- **최신 Figma가 기준이다.** 원본이 바뀌면 이전 결정이 있어도 최신본으로 재판정하고, 되돌린 결정은 §결정 로그에 남긴다.

## 용어

- <제품 도메인 용어와 Figma 표기의 대응. 예: "매장" = POI>

## 진행 규칙

- 위에서부터 순서대로 하나씩. 항목 착수 시 해당 Figma 화면 재확인 → 코드 재조사 → 작업 → 검증. 이 문서의 판정이 재조사와 다르면 문서를 고치고 진행한다.
- 검증 기준: <repo의 lint·typecheck·test 명령>.
- 기획 미정인 신규 도메인은 **대기** 그룹이다. 착수 조건이 풀리면 도메인 plan을 먼저 쓴다.

## Sync 상태

Figma가 갱신되면 스냅샷을 다시 받고 이 목록에 신규·변경 항목이 생겼는지 확인한다. 누락 추적은 이 절이 담당한다.

| 항목 | 값 |
|---|---|
| 마지막 pull | <YYYY-MM-DD> |
| Figma file version | `<version>` |
| 당시 규모 | 섹션 <N> · 화면 <N> · 기획 설명 <N>건 |

<YYYY-MM-DD> pull에서 반영된 변화: <한 문단. delta가 비어도 "변화 없음 (version만 갱신)"으로 쓴다>

**스냅샷이 구조적으로 담지 않는 축** — 여기 없다고 기획에 없는 것이 아니다. 판단이 걸리면 Figma를 연다.

- 코멘트 — 미결 논의가 코멘트에만 있다. 스크립트는 노드 트리만 받는다.
- 60자 미만 메모 — 짧은 화면 전이 지시·조각 메모는 떨어진다.
- 캔버스 낱개 목업 — 프레임으로 묶이지 않은 노드는 표에도 PNG에도 없다.
- 1000×600 미만 프레임 — 템플릿·컴포넌트 크기는 렌더되지 않는다.
- 중첩 섹션 라벨 — depth 2 섹션은 이름이 사라진다.
- <이 프로젝트에서 실제로 걸린 사례를 여기에 추가>

## 순서

**진행**: <화면 절 순서>.

**대기**: <착수 조건이 안 갖춰진 그룹 — 기획 미정 도메인, 외부 협의 대기 등>. 조건이 풀리면 진행 그룹으로 올린다.

## <섹션/화면 이름>

<YYYY-MM-DD> 조사: <현재 구현 요약 — 있는 것·없는 것을 file:line으로>

- [ ] <항목> — <Figma 근거(화면·기획 설명)> / <구현 근거 file:line> / <판정: 구현·문구만·skip 등>
- [x] <완료 항목> — <반영 commit/PR> (<YYYY-MM-DD>)

## <신규 도메인> (기획 중 — 착수 판단 대기)

<기획이 어디까지 왔는지, 무엇이 미정인지. 착수 조건이 풀리면 별도 도메인 plan을 쓴다>

## 결정 로그

- D1 (<YYYY-MM-DD>, 사용자) — <결정>. <근거>
- D2 (<YYYY-MM-DD>, Figma <version> 재판정) — <되돌린 결정 → 새 판정>. 되돌린 이유: <원본 변화>

## 확인 필요 (기획 내부 불일치)

- <화면 A와 기획 설명 B가 다르게 말하는 지점. 사용자/기획자 확인 전까지 판정 보류>
```

## 쓰는 법

- **§Sync 상태 표는 pull마다 갱신한다.** delta가 비어도 version은 바뀔 수 있고(Figma `version`은 내용 무변경으로도 올라간다), 이 행이 게이트의 기준이라 빠뜨리면 다음 실행이 같은 delta를 다시 미반영으로 판정한다.
- 결정 로그의 주체를 구분한다 — 사용자가 직접 말한 것과 Figma 재판정으로 바뀐 것은 다른 무게다.
- 화면 절의 항목은 Figma 근거와 구현 근거를 둘 다 가진다. 한쪽만 있으면 가설이다.
- 완료 항목은 지우지 않고 체크한다. 이 문서는 큐이자 이력이다.
